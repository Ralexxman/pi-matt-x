## D1. Список read-only инструментов не покрывает установленное окружение

`engine.ts:22`

```ts
const READ_ONLY_TOOLS = new Set(["read", "grep", "find", "ls", "ctx_read", "ctx_grep", "ctx_find", "ctx_ls"]);
```

`grantFor` возвращает `null` для всего, чего нет в списке. Дальше `needsPermission`
(`engine.ts:76`) решает: инструмент неизвестен, а фаза не даёт `bash` — значит спросить
пользователя.

Последствие: в фазе `grilling` (только `read`) вызов `ctx_search`, `symbol_search`,
`module_report`, `wiki_search` открывает диалог «Разрешить?». Модель уходит от этих
инструментов к `grep`, которого не хватает, или тревожит пользователя на каждом шаге.

Причина: список писался под ванильный Pi, а здесь стоит `pi-lean-ctx`, `pi-lens`,
`llm-wiki` и `hindsight`.

## D2. Мёртвое условие в `nextPhases`

`engine.ts:55`

```ts
return c.successors.filter((s) => contractOf(contracts, s) !== undefined || s);
```

`|| s` — непустая строка, всегда истинна. Фильтр возвращает весь список. Замысел был
отбросить наследников без контракта; код этого не делает и не может.

Последствие для поведения: нет. Последствие для чтения: строка обещает проверку,
которой нет, — ровно тот класс дефекта, что и в `SUB_SKILLS`.

## D3. `/skill:<имя>` ставит фазу без проверки имени

`index.ts:46`

```ts
pi.on("input", (event, ctx) => {
	const m = /^\/skill:([\w-]+)/.exec(event.text.trim());
	if (!m?.[1]) return;
	state.phase = m[1];
```

Имя не сверяется ни с `CONTRACTS`, ни с `SUB_SKILLS`.

Последствие: `/skill:implemet` пишет в состояние фазу без контракта. `contractOf`
возвращает `undefined`, все инструменты разрешены, а статусная строка показывает
`phase: implemet → —`. Охрана выключена, но выглядит включённой.

Второй случай: `/skill:research` — законный вызов, но он молча снимает ограничения
открытой фазы (`research` без контракта, значит `decide` не увидит нарушения).

## D4. Тесты вне `tsc`

`tsconfig.json:21`

```json
"exclude": ["extensions/**/*.test.ts"]
```

Комментарий объясняет: «их проверяет запуск». Запуск `node --test` стирает типы, а не
проверяет их. `index.test.ts` импортирует `ExtensionAPI` из Pi и приводит фейковый `pi`
через `as unknown as` — ошибка в этой обвязке всплывёт только в рантайме.

Проверка: `tsc -p` с тестами в `include` проходит без ошибок. Значит исключение не
нужно.

## Спорные

### D5. `ctx_edit` → `write`

`engine.ts:30`: `if (tool === "write" || tool === "ctx_edit") return "write";`

У Pi `edit` и `write` — разные инструменты, и `ctx_edit` — это поиск-и-замена, то есть
`edit`. Сегодня разницы нет: ни один контракт не даёт `edit` без `write`. Разница
появится, если появится фаза «правим существующее, новое не создаём». Тогда `ctx_edit`
в ней будет заблокирован, а `edit` разрешён — несогласованно.

Варианты: (а) считать `ctx_edit` через `edit`; (б) оставить как есть, пока нет такой
фазы; (в) убрать различие `write`/`edit` из модели возможностей.

### D6. Цитата гейта — не условие конца

`contracts.ts:44` — `grilling`:

> Work the tree in **rounds**. The **frontier** is every decision whose prerequisites are already settled…

Это описание процедуры, а вопрос рядом: «Интервью закончено?»

`contracts.ts:69` — `grill-with-docs`:

> Skill tool twice, for "grilling" and "domain-modeling"

Это тоже инструкция, а не критерий готовности.

Остальные шесть цитат — настоящие условия конца (`Check with the user that these
seams match…`, `Each slice is sized to fit in a single fresh context window`).

Последствие: в двух фазах пользователь видит доказательство, которое не отвечает на
заданный вопрос, — и отвечает «да» на глазок. Гейт держится на цитате; если цитата не
та, механизм не работает.

Правка требует других цитат из тех же файлов, то есть решения, а не строки.

### D7. Из фазы нельзя выйти

`implement`, `code-review`, `diagnosing-bugs` перечисляют в наследниках `retro`, `pr`,
`handoff`. У этих трёх контрактов нет — они есть в `~/.agents/skills`, но не в
`CONTRACTS`.

`engine.ts:92`: скилл без контракта не меняет фазу. Значит после входа в любую фазу
сессия остаётся ограниченной до конца: вернуться к обычной работе нельзя, `/reload`
или новая сессия — единственный выход.

Варианты: (а) контракты для `pr`/`handoff`/`retro` с пустыми `grants` и `successors` —
выход из флоу как фаза; (б) невидимая фаза «вне флоу», в которую ведёт любой скилл без
контракта, если пользователь так сказал; (в) явная команда снятия охраны.

Пункт (б) уже почти сделан: `decide` для скилла без контракта возвращает `phase:
state.phase`. Достаточно одного решения — что считать выходом.

### D8. Ответ на гейт выбрасывается

`index.ts:60`: ответ редактора уходит в `gatesPassed.push`, текст теряется.

В `GLOSSARY.md` «Обход» определён как «осознанный отказ от гейта с записанной причиной».
Сейчас записывается только факт, не причина.

Последствие: в отчёте о сессии не видно, на каком основании фаза закрыта. Правка на
две строки (хранить ответ и показывать в статусе), но пока неясно, нужен ли он вообще.
